# 仕様書

## 目的

naoiwのWebアプリ作品一覧と、Markdownで管理する技術メモを公開する。

## ページ

- `/` — 制作物の一覧、カテゴリ絞り込み、外部アプリとGitHubリポジトリへのリンク
- `/blog/` — 公開日の新しい順にMarkdown記事を表示。日付、タイトル、概要、タグを掲載
- `/blog/[slug]/` — 個別記事。公開日・更新日・タグ・本文・一覧への戻りリンク
- `/develop/` と `/develop/blog/` 以下 — 同じ構成の開発プレビュー（noindex）
- 全ページの共通ナビゲーションは「制作物」「技術メモ」
- RSS、記事検索、タグ別一覧、ブラウザ内エディタは初期実装の対象外

## 作品データ

`app/projects.json` の配列で管理。表示順は配列順。
分類は`dashboard` / `tool` / `game` / `experiment`。
`id`・`name`・`description`・`category`・`initials`・`url`・`repository`が必須で、
任意で`status`を指定できる。外部リンクはHTTPS。

## Markdown記事

`content/posts/<slug>.md`からビルド時に自動収集する。
ファイル名`slug`は小文字英数字とハイフンのみ。URLは`/blog/<slug>/`。

Front Matterは先頭の`---`ブロック。サポートするメタデータ：

| フィールド | 必須 | 内容 |
| --- | --- | --- |
| `title` | 必須 | タイトル（空文字不可） |
| `date` | 必須 | 公開日、`YYYY-MM-DD` |
| `description` | 必須 | 一覧・SEOに表示する説明 |
| `updated` | 任意 | 更新日（公開日以降） |
| `tags` | 任意 | `- タグ名`形式のリスト |

メタデータの形式は単純なYAMLサブセットで、入れ子・オブジェクト・インライン配列を扱わない。
記事本文では見出し、段落、強調、リンク、画像、コード、水平線、リスト、引用、表を表示する。
未対応の複雑なMarkdown構文はそのままテキストになる場合がある。
**生HTMLは解釈しない。**リンク・画像URLはhttp(s)、メールリンク、ページ内アンカー、ルート相対パスだけ許可する。
ルート相対の画像・リンクはプレビュー時に`/develop`を自動付与する。

記事一覧は`date`の降順、同日はslugの昇順。日付の入力がなければエラーにし、
Gitのファイル更新日時には依存しない。記事の生成は静的ビルドのみ、実行時のGitHub API呼び出しは行わない。

## デザイン・アクセシビリティ

- 共通ダークテーマ、ヘッダー・フッター・レスポンシブ幅を作品一覧と共有
- 制作物カードはPC3列／中間2列／スマホ1列
- ブログは読みやすさを優先して本文幅を狭める
- リンクのキーボードフォーカス、日時の`time`要素、記事・見出しの意味構造を設定

## メタデータ・SEO

- 記事ごとにtitle、description、canonical、OGPを生成
- サイトマップには`/`・`/blog/`と全記事URLを含める
- プレビューはnoindex。本番URLをcanonicalとして保持
